 # LEO Orbital Decay & Deorbit Compliance Tool
    #### Video Demo: https://youtu.be/GUk5MXVFhlI
    #### Description:
    The LEO Orbital Decay & Deorbit Compliance Tool is a Python-based software application designed to evaluate the orbital lifetime and atmospheric re-entry of satellites operating in Low Earth Orbit (LEO). Space debris has become a critical problem for modern space missions. If we leave all the satellites that we send into space, our planet would be completely blocked by all this garbage. This is the reason why governments and organizations such as ESA and FCC have established the "5-year rule", which says that defunct satellites must naturally decay and re-enter the atmosphere within five years to prevent orbital congestion. This project uses key spacecraft parameters such as initial orbital altitude, dry/wet mass, cross-sectional frontal area, and drag coefficient and calculates essential orbital metrics. The code computes the spacecraft's ballistic coefficient (b), evaluates real-time air density using an exponential model, estimates the required speed (delta-v) for emergency active deorbit maneuvers, and performs a numerical simulation of altitude loss over time. Finally, the tool generates a clean tabular summary in the terminal and outputs an automated trajectory plot (decay_plot.png) to visualize the satellite's descent curve down to the 120 km Kármán re-entry interface (Kármán line is where it is considered that satellites disintegrate). To summarize, the purpose of the project is to know if a certain satellite (knowing mass and area of it and the altitude where it is orbiting) is going to disintegrate within the next 5 years and comply with the regulations.
    The project is structured into three main files:
    project.py: this is the core of the project. It consists of five different functions:
    - main: prompts the user for the parameters of the satellite and evaluates if they are valid, if not it exits via "sys.exit". Calls the other four custom functions. It also says if the satellite is compliant or non-compliant. Inside main, "project.py" formats the output into a clean ASCII table using tabulate and generates an automated trajectory visualization (decay_plot.png) using matplotlib.
    - get_ballistic_coefficient: calculates the spacecraft's ballistic coefficient
    - get_density: Estimates thermospheric air density using an exponential atmospheric model.
    - get_deorbit_deltav: Calculates the speed change required for a Hohmann transfer deorbit maneuver.
    - simulate_decay: Runs a day-by-day numerical integration loop tracking the satellite's orbital decay down to the 120 km Kármán line.
    test_project.py: this file tests project.py. It implements separate test functions (test_get_ballistic_coefficient, test_get_density, test_get_deorbit_deltav, and test_simulate_decay) for each of the functions in project.py that validate mathematical precision using pytest.approx and checks tht invalid inputs raise "ValueError".
    requirements.txt: list of the external libraries required to run the project.
    Design choices and assumptions made in the project:
    1º Piecewise exponential atmosphere vs complex models: Implementing a full MSISE thermospheric model would exceed the scope of CS50P. Instead, a piecewise exponential model was chosen because it accurately captures density decay across different LEO altitude bands while remaining computationally efficient.
    2º Day by day numerical integration: A daily time-step loop was chosen to balance sufficient trajectory precision for multi-year orbital decay estimation with fast execution efficiency. A second by second or orbit by orbit numerical integrations could have been chosen, but we would have sacrificed the efficiency of the project.
    3º Strict input validation: to ensure physical validity, rigorous "ValueError" checks were implemented across all functions, handled via sys.exit.
